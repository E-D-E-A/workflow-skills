Craft skills

The two skills that aren't about a tool: pulling a fuzzy idea apart before you build it, and writing the skills themselves.

What's in it

Every other plugin here wraps a tool and ships its connector. This one wraps neither — it's how we work, not what we work in.

grillingInterviews you relentlessly, one question at a time, until a fuzzy idea is sharp. Everyone.
skill-writingHow to write and edit a skill in this marketplace. The two developers.

Grilling

Say "grill me" about a plan, a decision, or an idea you can't yet describe cleanly.

Reach for it when the answer to "what does done look like?" is a shrug.

It asks one question at a time and waits — several at once gets shallow answers to all of them. Every question comes with a recommended answer, so you're agreeing, correcting or picking rather than writing an essay.

It looks facts up itself. It'll never ask you to name a team, a status or a label it could have listed. Your time is for the calls only you can make.

It won't start work. Grilling produces understanding; once you agree you've got it, hand off to linear-issue or confluence-write to write the thing.

How it differs from the gates

linear-issue and confluence-write already stop and ask when a field is missing. Grilling is for when the whole idea is fuzzy, not one blank.

Writing a skill

For the two developers. The full rules live in CLAUDE.md — this is the shape of the loop.

  1. Pick the plugin

    About a tool → that tool's plugin, which carries its connector. About how we work → edea-craft. Needs a new connector → you're adding a plugin, not a skill.

  2. Write the description

    It's the only part Claude sees before deciding to use the skill, so it does all the firing. Say the job concretely, then name the triggers in the words people actually say.

    Never fires → the triggers don't match real language. Fires too often → they're too broad. Both are fixed here, not in the body.

  3. Write the body

    • End every step on something checkable — or Claude declares it done early
    • Say what to do, not what to avoid
    • Reuse the same words — Outcome, Next action, Waiting, ENG, BIZ
    • Only what every run needs goes in SKILL.md

  4. Apply the house rules

    • Plain language — two of the people relying on this aren't developers
    • Look values up, never hardcode — a hardcoded status breaks quietly on rename
    • Gate on missing information — ask with suggested answers, don't guess
    • Guard anything destructive — confirm, and offer the reversible option first

  5. Cut it down

    Line by line: does this change what Claude does versus saying nothing? "Think carefully" buys nothing. Delete whole sentences rather than trimming words.

  6. Check it actually fires

    A skill nobody triggers fails silently — installed, never runs. validate won't catch it; that only checks the files are well-formed.

    Write five prompts in the words people here would really use, then read the description cold and ask whether it fires on each. Fix the description, not the body.

  7. Ship it

    Docs page if people can see the change → bump version in that plugin's plugin.json → claude plugin validate . → push.

The one that can't be undone

This repo is public and its history is permanent — going private later doesn't unpublish what forks and caches hold.

Never write target markets, customer names, pricing, kill criteria or anything venture-specific into a skill file. If a skill genuinely needs it, that's the signal to start a second private marketplace, not to phrase it carefully.

Install

/plugin marketplace add E-D-E-A/workflow-skills
/plugin install edea-craft@edea

No sign-in — this plugin ships no connector. Then /plugin → Marketplaces → turn on auto-update.
