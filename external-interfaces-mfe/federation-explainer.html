A micro frontend can use other composition mechanisms, such as an iframe or server composition. Module Federation is one option; it can also share modules that are not UI features.

Tradeoff to mention in interviews: this split earns its complexity when independent ownership, releases or reuse matter. For a small feature maintained and released with one host, a normal component/package may be simpler.

30-second explanation

“We designed the external-interface status area as one micro frontend containing the whole list. The host loads its separately built code using Module Federation, then mounts a Vue Web Component in the navbar. Vue and Vuetify are shared dependencies. The host passes its existing WebSocket manager and a message normalizer; the remote fetches metadata, subscribes once and keeps its own state. This supports separate releases and reuse across clients, while making compatibility and runtime failures explicit concerns.”

Expand to a 90-second explanation
  • Loading: the host loads remoteEntry.var.js, resolves the exposed ./register module and runs its code in the same page.
  • Mounting: defineCustomElement wraps the Vue UI as cust-external-interfaces. The host passes JSON config and live JavaScript properties before mounting.
  • Sharing: singleton settings coordinate compatible Vue/Vuetify root dependencies. Each remote element still has local component state and its own Vuetify plugin instance.
  • Data: REST supplies metadata; the host’s normalizer converts raw messages into { id, connectionStatus }. Early updates are buffered so REST does not overwrite them.
  • Cleanup: unmount removes the listener, not the shared connection. Pending REST results are ignored after unmount.
  • Limits: independent deployment needs stable contracts, compatible libraries and cache management. A Web Component in light DOM is not a security or CSS isolation boundary.

Follow-up questions you may get

Why a single collection remote?

The current manager allows one consumer per topic. One collection needs one subscription and can update the matching row internally. Per-interface remotes would require changing that ownership model or adding fan-out.

Why pass a normalizer?

Clients can have different raw message shapes. The host understands its envelope; the remote understands one small normalized contract. The normalizer returns a value, and the remote owns the state change.

Does singleton mean shared application state?

No. It coordinates a library instance in a federation share scope. It does not create a shared store, share component refs, or automatically share the host’s Vuetify plugin instance.

Is this like an iframe?

No. Federated JavaScript executes in the host page. Our light-DOM Web Component shares the document and inherits theme variables. It is a UI integration boundary, not a sandbox.

What remains coupled?

The exposed module name, tag, properties, normalized messages, emitted events and shared library versions. Teams must govern these contracts even when builds and deployments are separate.
